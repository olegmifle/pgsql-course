# Самопроверка после собственной попытки

Здесь находятся один вариант решения и SQL-пробы для каждой стадии. Если в вашей схеме ограничения названы иначе, замените их имена в проверках перед запуском.

- `01-protect.sql` — ключи и составная ссылка с NOT VALID.
- `02-repair.sql`, `repair-core.sql` — исправление заказа и повтор после COMMIT, остановка при противоречии между заказом и аудитом, затем VALIDATE. Временная функция в repair-core.sql позволяет проверять отказы. В своём решении можно использовать DO или другой транзакционный SQL.
- `03-expand.sql` — добавление колонки с суммой в рублях.
- `04-cutover.sql` — финальная сверка сумм и установка ограничений перед переключением чтения.
- `05-rollback.sql` — изменения схемы для возврата старого приложения с сохранением проверок организации клиента и номера заказа.
- `queries.sql` — диагностические запросы, выполнять отдельно на нужной стадии.
- `checks-*.sql` — проверки схемы и данных на каждой стадии, включая ошибку записи аудита и противоречия.
- `run.sql` — запуск всего решения на отдельной пустой базе, включая повтор исправления и возврат старой версии.

## Посмотреть отдельную стадию

Сравните соответствующий файл со своим решением. Проверки `checks-*.sql` работают в BEGIN/ROLLBACK и не сохраняют тестовые изменения. Файлы 01/03/04/05 меняют схему и данные, поэтому их запускают один раз в каждой базе. Файл 02 можно повторить после COMMIT: заказ и аудит останутся без изменений.

## Запустить готовое решение целиком

Из корня пакета при запущенном Compose создайте другую пустую базу:

```sh
docker compose exec -T postgres createdb -U course course_hw04_reference
docker compose exec -T postgres psql -X -U course -d course_hw04_reference -v ON_ERROR_STOP=1 -f /work/self-check/run.sql
```

Своя работа в course_hw04 сохранится. Для ещё одного запуска выберите новое имя базы в обеих командах. Скрипт не очищает существующую базу. Для установленного PostgreSQL можно выполнить `psql -X -d ИМЯ_ПУСТОЙ_БАЗЫ -v ON_ERROR_STOP=1 -f self-check/run.sql`.

После успешных SQL-проб выводятся сообщения OK и OK SQLSTATE. При неожиданном результате скрипт останавливается. Обоснование решений и остановку внешнего импорта нужно проверить отдельно. Пробы отказов вызывают ту же функцию исправления, которую использует 02-repair.sql; изменения каждой такой пробы откатываются.
