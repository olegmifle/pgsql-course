## Что установить

Нужны запущенный Docker с Compose v2, терминал и редактор для чтения SQL. Для урока 7 дополнительно нужен Python 3.10+ на компьютере; внешних Python-библиотек нет. PostgreSQL и `psql` работают в контейнерах. Для первой загрузки образов и сборки урока 7 нужен интернет. Оставьте несколько гигабайт для образов и данных; самый большой набор — в уроке 5.

Проверьте окружение:

```sh
docker info
docker compose version
```

## Как работать

1. Откройте папку нужного урока, где находится его `compose.yaml`. Все shell-команды его README выполняются из этой папки.
2. Запустите стенд и подготовку по инструкции урока. Уроки независимы: сначала проходить предыдущие для запуска не требуется.
3. Прочитайте SQL очередного шага, предположите результат, затем выполните его и сопоставьте наблюдение с пояснением.
4. Если указаны окна A/B/O, откройте отдельное подключение `psql` в каждом терминале. A/B выполняют операции, O наблюдает. Не заменяйте их отдельными одноразовыми вызовами: открытые транзакции и временные таблицы принадлежат подключению.

Команды `docker compose …` вводят в обычном терминале. Команды `\i …`, `\set …`, `\q` и SQL — внутри `psql`. Путь `/work` существует **в контейнере** и соответствует текущей папке урока. `\i` выполняет файл, `\q` закрывает подключение, `ROLLBACK;` отменяет текущую транзакцию. Знак `*` в приглашении `psql` означает открытую транзакцию, `!` — транзакцию после ошибки.

По умолчанию порты компьютера не публикуются. Каждый урок имеет отдельное имя Compose-проекта и свою базу; команды не требуют локальных путей автора или других файлов курса. Учебные роли и пароли уже заданы в Compose. Эти стенды предназначены для локальных экспериментов.

## Как читать результаты

Сравнивайте значения, число строк, SQLSTATE, узлы плана и объём работы. PID, transaction ID, позиции WAL, точные размеры и время зависят от запуска. Время из чужого результата не является нормативом.

В опытах с ожидаемыми ошибками выполняйте шаги отдельно и проверяйте сам SQLSTATE. После ошибки внутри транзакции нужен `ROLLBACK;`, затем новая попытка целиком. Не запускайте рекурсивно все SQL подряд: некоторые файлы специально оставляют транзакцию открытой или ждут другое окно.

## Остановка и повтор

Выйдите из всех подключений через `\q`, затем в папке урока выполните:

```sh
docker compose down
```

Для уроков 1–6 и 8 данные в именованном томе сохраняются. Повторная подготовка зависит от урока и описана в его README. В уроке 7 данные живут внутри контейнера: `down` удаляет их, а следующий `up` готовит стенд заново.

Если Docker недоступен, проверьте, что запущен Docker Desktop или выбран ваш рабочий Docker-контекст. При ошибке запуска начните с `docker compose ps` и `docker compose logs`. При `25P02` найдите первую ошибку и выполните `ROLLBACK;`. Если один запрос ждёт, продолжите действия в другом окне по инструкции.

Эта папка — корень готового репозитория. Скопируйте её содержимое в свой репозиторий вместе с `.gitignore`. Папки результатов, локальные настройки и логи исключены из Git. Для воспроизведения достаточно файлов этого пакета.
