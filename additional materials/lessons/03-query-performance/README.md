# Урок 3. Уменьшаем работу запроса без индексов

Пять демонстраций сравнивают запросы с одинаковым результатом. Для каждой пары есть исходный SELECT в `sql/NN-before.sql`, переработанный в `sql/NN-after.sql`, готовые EXPLAIN в `plans/` и проверка результата в `checks/`. Это полный разбор для повторения: заполнение заготовок не требуется.

## Подготовка

Из этой папки выполните:

```sh
docker compose up -d --wait
docker compose exec -T postgres psql -X -U course -d course_live03 -v ON_ERROR_STOP=1 -f /work/schema.sql -f /work/seed.sql -f /work/settings.sql -f /work/sanity.sql
docker compose exec postgres psql -X -U course -d course_live03 -v ON_ERROR_STOP=1
```

В открытом `psql`:

```sql
\pset pager off
\i /work/settings.sql
```

Схема `lab`: 1 200 клиентов, 48 000 заказов, 142 518 позиций, 96 001 платёж и 380 608 событий. Индексов нет, включая PK. Это условие эксперимента; уникальность ID и связи готового набора проверяются в `sanity.sql`. Settings задаёт общие условия сравнения и должен применяться в каждом новом подключении.

## Как пройти одну пару

Для первой пары внутри `psql` выполните:

```sql
\i /work/plans/01-before.sql
\i /work/plans/01-after.sql
\i /work/checks/01.sql
```

Для остальных замените `01` на `02`, `03`, `04`, `05`. Перед запуском прочитайте соответствующие SELECT. Q1 делает много повторных сканов, поэтому может занимать заметно больше времени.

В проверке должны совпасть `before_rows` и `after_rows`, а `before_minus_after` и `after_minus_before` должны быть нулями. Двусторонний EXCEPT ALL учитывает кратности. Это проверка значений на учебных данных; совпадение типов, смысл пустых наборов и порядок выдачи требуют отдельного разбора. Для описания колонок можно ввести SELECT без финальной точки с запятой и на новой строке выполнить `\gdesc`.

## Что увидеть в пяти опытах

| Пара | Изменение | Что искать в плане | Строк результата |
| --- | --- | --- | ---: |
| 01 | Два коррелированных агрегата → одна агрегация и LEFT JOIN | В исходнике сканы orders с `loops=1200`; после один проход и сохранение всех клиентов | 1 200 |
| 02 | JOIN + DISTINCT → независимые EXISTS | Устраняется размножение комбинаций и финальный DISTINCT | 20 346 |
| 03 | MATERIALIZED CTE с payload → прямой отбор | Исчезает промежуточное хранение почти всего events; сравните temp buffers | 1 586 |
| 04 | Агрегация всей истории → отбор заказов до агрегации | Меньше входных строк и групп при прежнем чтении таблиц | 545 |
| 05 | Ранжирование всех событий → события нужных заказов | Уменьшается вход сортировки; полный порядок выбирает одну последнюю строку | 541 |

В 01 LEFT JOIN и COALESCE сохраняют клиентов без оплат. В 02 нужны факты наличия, поэтому колонки дочерних строк не выводятся. В 04 `count(i.id)` даёт ноль для заказа без позиций, тогда как `count(*)` дал бы единицу. В 05 `occurred_at DESC, id DESC` разрешает совпадающие времена; DISTINCT ON — один из способов записать этот контракт. Основной выигрыш даёт уменьшение входа, а не само название конструкции.

## Как читать EXPLAIN

Читайте план снизу вверх. `actual rows` обычно дано за один `loop`; учитывайте повторения. Буферы родителя уже включают работу дочерних узлов — не складывайте все строки плана. Сначала сравните сканирования, фильтры, объём JOIN/агрегации/сортировки и временные файлы, затем время. Выполните обе версии несколько раз в одном окружении: прогрев кешей влияет на замеры.

Самостоятельно объясните, почему исчезновение temp в 03 связано с удалением материализации, а одинаковые shared buffers в 04 совместимы с уменьшением работы агрегации.

## Контрпримеры SQL

```sql
\i /work/diagnostics.sql
```

Проверьте: NOT IN с NULL даёт 0 вместо 8 229 у NOT EXISTS; заказ 97 без позиций даёт `count(*)=1`, `count(i.id)=0`; размножение позиций платежами заказа 7 удваивает сумму 6 000 до 12 000; события 55 и 56 имеют одинаковое время; обычный EXCEPT теряет различие кратности, EXCEPT ALL сохраняет.

## Повтор и завершение

Все пары только читают данные и допускают повторный запуск. Schema и seed выполняются один раз. Для полной повторной загрузки создайте новую пустую базу и используйте её в подготовке и подключении:

```sh
docker compose exec -T postgres createdb -U course course_live03_repeat
docker compose exec -T postgres psql -X -U course -d course_live03_repeat -v ON_ERROR_STOP=1 -f /work/schema.sql -f /work/seed.sql -f /work/settings.sql -f /work/sanity.sql
```

Выход из psql — `\q`, остановка — `docker compose down`. Данные сохраняются.
