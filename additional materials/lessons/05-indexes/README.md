# Урок 5. Индексы и цена чтения

Восемь самостоятельных опытов показывают, как индекс меняет объём чтения, сортировку и доступ к heap. Исходные данные: 1 000 000 заказов, 100 000 покупателей и 600 000 событий. Изначально есть только три PK.

## Подготовка

Из этой папки выполните:

```sh
sh ./start.sh
docker compose exec postgres psql -X -U course -d live5
```

Первый запуск создаёт данные; повторный сохраняет их и пропускает загрузку. В Debian-образе PostgreSQL задана `en_US.utf8`: она нужна для опыта с текстовым B-tree и `text_pattern_ops`. Порты компьютера не публикуются; клиент работает внутри контейнера.

## Порядок работы

В `psql` включите остановки:

```sql
\set pause_demo on
```

Перед очередным Enter прочитайте SQL по таблице ниже: файлы `show/` открываются в редакторе на компьютере. Управляющие сценарии `core/` сами выполняют эти фрагменты в нужном порядке и задают параметры вроде QR и курсора страницы. Отдельный запуск всех `show/` подряд не воспроизводит опыт.

| Опыт | Команда в psql | Файлы для чтения | Что объяснить |
| --- | --- | --- | --- |
| 1. Цена | `\i /work/core/01_price.sql` | `show/01`–`03` | Узкий и широкий диапазон: почему один B-tree полезен не одинаково |
| 2. B-tree/hash | `\i /work/core/02_btree_hash.sql` | `show/04`–`08` | Равенство и диапазон; hash не поддерживает упорядоченный диапазон |
| 3. Текст | `\i /work/core/03_patterns.sql` | `show/09`–`12` | Префикс, `text_pattern_ops`, подстрока и `pg_trgm` |
| 4. Составной ключ | `\i /work/core/04_composite.sql` | `show/13`–`18` | Порядок полей для статуса/диапазона и общей ленты; keyset |
| 5. Partial | `\i /work/core/05_partial.sql` | `show/19`–`21` | Индекс редкой очереди и его размер |

`show/01` означает файл с этим числовым префиксом, например `show/01_price_query.sql`. Полные имена можно посмотреть в папке `show/`.

Для первого прохода последовательно выполните **04 → 05 → 06**, затем остальные опыты. Каждая сцена задаёт UTC и search_path, пересоздаёт свои индексы и допускает отдельный запуск после подготовки. Предыдущие сцены могут оставить другие индексы: читайте фактический выбранный план.

## На что смотреть

- Узлы Index Scan, Bitmap Scan, Seq Scan и Sort; сколько строк просмотрено и отброшено.
- `Buffers`: объём обращений к страницам; read не обязательно означает физический диск.
- `Heap Fetches`: покрывающий индекс сам по себе не гарантирует чтение без heap. Видимость строк проверяется по visibility map; UPDATE снимает соответствующие отметки, VACUUM может их восстановить.
- Размер индекса и его назначение: индекс под очередь не обязательно заменяет индекс общей ленты.
- У keyset должны совпадать поля полного порядка и условия продолжения; `id` разрешает одинаковое время.

Планировщик использует обычные настройки. В сцене 02 есть отдельное сравнение `SET LOCAL enable_seqscan=off` в транзакции с ROLLBACK — это приём исследования доступного пути. Миллисекунды и выбранные планы зависят от машины; вывод должен опираться на реальную работу.

Сцена 06 обновляет payload у 20 строк и временно отключает autovacuum таблицы для наблюдения. В конце возвращает настройку. При прерывании этой сцены повторите её до завершения.

## Повтор и завершение

Повторите нужный `\i`. Для выполнения без остановок:

```sql
\set pause_demo off
\i /work/core/04_composite.sql
```

Для нового набора закройте прежнее подключение и создайте отдельную базу:

```sh
docker compose exec -T postgres createdb -U course live5_repeat
docker compose exec -T postgres psql -X -U course -d live5_repeat -v ON_ERROR_STOP=1 -f /work/core/00_prepare.sql
docker compose exec postgres psql -X -U course -d live5_repeat
```

Во всех дальнейших подключениях используйте новую базу; схема остаётся `live5`. Для следующего повтора выберите ещё одно имя. `00_prepare.sql` не перезаписывает существующую схему. Выход — `\q`, остановка — `docker compose down`.
