# Урок 1. Реляционная модель и ограничения

На примере пользователей, курсов и регистраций проверим, какие правила защищает сама база. Нужен один терминал. Схема и данные уже готовы: задача — выполнить демонстрацию и объяснить результаты.

## Подготовка

Все shell-команды выполняйте из этой папки:

```sh
docker compose up -d --wait
docker compose exec -T postgres psql -X -U course -d course -v ON_ERROR_STOP=1 -f /work/sql/01_schema.sql -f /work/sql/02_seed.sql
```

Подготовка применяется один раз к пустой базе `course`. `users` и `courses` — родители, `enrollments` связывает пользователя с курсом и хранит сумму в копейках, статус и время регистрации.

## 1. Проверить правильные данные

Откройте `sql/01_schema.sql` и найдите PK, FK, UNIQUE, NOT NULL и CHECK. Затем выполните:

```sh
docker compose exec -T postgres psql -X -U course -d course -v ON_ERROR_STOP=1 -f /work/sql/03_sanity.sql
```

Ожидается:

- 3 пользователя, 2 курса, 3 регистрации; нет сирот, повторных пар и недопустимых значений.
- Оплативший `postgres-dev` — `anna@example.test`; пользователь без регистраций — `vera@example.test`.
- Число регистраций: `postgres-dev = 2`, `sql-basics = 1`.

JOIN собирает представление из связанных таблиц. Отдельная таблица регистраций хранит факты связи; UNIQUE по `(user_id, course_id)` выражает правило, которое один искусственный PK не обеспечивает.

## 2. Проверить отказы

Прочитайте `sql/04_invalid_writes.sql`. В нём шесть независимых неверных записей. Перед каждой определите, какое ограничение должно её отклонить.

```sh
docker compose exec -T postgres psql -X -U course -d course -v ON_ERROR_STOP=0 -v VERBOSITY=verbose -f /work/sql/04_invalid_writes.sql
```

Здесь ошибки ожидаемы, поэтому остановка при первой отключена. Правильная последовательность SQLSTATE:

| Попытка | Ограничение | SQLSTATE |
| --- | --- | --- |
| Повтор пары пользователь/курс | UNIQUE | `23505` |
| Неизвестный пользователь | FOREIGN KEY | `23503` |
| Отрицательная сумма | CHECK | `23514` |
| NULL вместо суммы | NOT NULL | `23502` |
| Статус вне словаря | CHECK | `23514` |
| Повтор email | UNIQUE | `23505` |

Повторите `03_sanity.sql`: число строк остаётся 3/2/3. Код выхода команды с `ON_ERROR_STOP=0` сам по себе не подтверждает правильность: сверяйте все шесть ошибок. Пропуски в identity после отказов допустимы.

## Самопроверка

Объясните, почему FK и NOT NULL нужны вместе, почему PRIMARY KEY регистрации не запрещает повтор пары и почему проверку суммы полезно хранить в базе.

## Повтор и завершение

Проверки можно запускать повторно. Для повторного создания схемы заведите другую пустую базу:

```sh
docker compose exec -T postgres createdb -U course course_repeat
docker compose exec -T postgres psql -X -U course -d course_repeat -v ON_ERROR_STOP=1 -f /work/sql/01_schema.sql -f /work/sql/02_seed.sql
```

В дальнейших командах используйте `-d course_repeat`. Для следующего повтора выберите ещё одно имя. Остановка: `docker compose down`; том сохраняется.
